## Small DM correction

The displayed Retry notice identifies a failed `resolve_my_push_notification` RPC, before Messaging navigation. The original implementation allowed one five-second read; any error immediately required a reload. Retry then successfully resolved the same notification. No original phone HTTP status/timing was captured, so the precise initial mobile failure is **not proven**. There is no evidence that the peer destination or DM permission was incorrect.

`PushNotificationEntry` now retries that read **once**, only for network/abort status 0, HTTP 408/429 or 5xx. Each attempt retains a five-second bound, reads the current session and pins its bearer token; after each result it rechecks account identity. Effect cleanup aborts the request and prevents stale navigation. A new account resolves through its own authorization; it never inherits an old-account destination. HTTP 401/403 and unavailable content are not automatically retried. Persistent errors retain the existing manual Retry/Dismiss experience. No automatic notification resend, source read bypass, auth relaxation or destination changes.

The correction uses ordinary AbortController and timers rather than introducing AbortSignal.any, preserving the existing iOS support floor. Messaging and Job Update entry still use their existing actual components and owner-authenticated resolver. Preview, generation, revocation and transport delivery contracts remain unchanged by this client correction.
