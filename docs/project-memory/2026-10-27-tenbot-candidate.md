## Architecture and release knowledge

`supabase/functions/_shared/tenbot-knowledge.ts` owns compact employee-safe capability excerpts. Entries distinguish deployed, permission-restricted (server capability check), local/unreleased, planned/deferred and unknown. The snapshot pins the last verified Production runtime `f8f78c5`, supported by the executed push reliability receipt. It does not inherit local dev availability. Source receipts remain in engineering documentation, never sent wholesale to the provider. Employees see a source title, revision, verification date and valid module link where guidance is verified.

Conventional token-ranked retrieval selects at most three authorized excerpts. At this scale an in-memory server registry avoids a second database copy and synchronization failure; PostgreSQL full-text search can replace retrieval behind this interface when corpus size justifies it. The model selects excerpt IDs; the server renders vetted workflow text, status and links. AI never establishes release state or permissions. An invalid/out-of-scope ID fails closed. Unverified routes are omitted. The client bundle does not contain the server registry or internal evidence paths.

Release update process: the release owner updates affected registry entries, source receipt and snapshot revision **after** verifying deployment, in the same release evidence change. Preserve existing unknown entries until exact employee controls are verified. Do not import Current State wholesale: it mixes deployed, local and deferred work. The focused verifier checks evidence paths, routes and status boundaries. Registry copy is the one employee guide; receipts are supporting evidence, not a parallel employee guide. Snapshot freshness requires a release gate review; a dev build never promotes entries automatically.

## Provider and cost verification — October 27

Selected `@cf/meta/llama-3.1-8b-instruct-fp8`: an available small 8B instruction model in the [Cloudflare catalog/model page](https://developers.cloudflare.com/workers-ai/models/llama-3.1-8b-instruct-fp8/), with 32k context. The faster 8B variant appeared in pricing but was absent from the current model catalog, so it was not selected. [Model pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/) is $0.152/M input and $0.287/M output tokens. Native JSON support is inconsistently documented; the adapter requests JSON through instructions and strictly parses/validates the response rather than assuming schema enforcement. Cloudflare failure/invalid JSON is an unavailable response, never a fabricated AI answer.

At 2,000 input and 300 output tokens, one answer costs approximately $0.0003901 before free allocation; 10,000 such answers cost about $3.90. This is an estimate, not measured usage. [Free quota](https://developers.cloudflare.com/workers-ai/platform/pricing/) is 10,000 Neurons/day, resets at 00:00 UTC and is account-shared; beyond it requires Workers Paid, with $0.011/1,000 Neurons. [Default text generation limit](https://developers.cloudflare.com/workers-ai/platform/limits/) is 300 requests/minute. No subscription purchased. Account-specific quota/credentials and actual inference availability have not been tested.

Server-only environment: `TENBOT_CF_ACCOUNT_ID`, `TENBOT_CF_AI_TOKEN` (Workers AI Run permission), `TENBOT_MONTHLY_BUDGET_USD` (default zero, maximum 100), `TENBOT_ALLOWED_ORIGINS`, plus existing Supabase URL/anon/service configuration. No credentials are available through task-specific configuration. No real inference call is claimed. Activation requires separately approved Edge deployment/secrets, migration application, origin allowlist and budget. No new always-on infrastructure is needed.

Provider abstraction is independent of Cloudflare. No tools, business-data client or privileged credentials enter the model payload. Only question, last two employee questions, and three permitted guide excerpts are sent. Conversation remains in component memory, is bounded to eight turns and clears on account change. No chat prompt/response storage. Feature drafts alone are persisted after explicit employee confirmation.

## Feedback and security

Forward migration `20261027120000_tenbot_feedback_usage.sql` creates feedback, append-only review history and usage reservation tables. It does not alter existing roles, business tables, private Inbox or task policies. Existing `manageUsers` capability is the proposed review boundary for authorized administrators; no Product Owner role is invented. Product must confirm whether an additional explicitly granted reviewer capability is wanted before release.

Tables have RLS and no direct anonymous/authenticated grants. Caller RPCs derive submitter UUID/name from Auth and active app membership, require confirmation and bounded fields, reject forged identity fields, throttle submissions, restrict listing/review to `manageUsers`, and preserve original draft/history. Status changes do not create tasks or change the roadmap. Lists are capped at 100 newest matching requests; pagination is a future scale concern.

Atomic server-only usage RPCs serialize reservations across Edge isolates: six inference attempts/user/minute and a configured global monthly cap. Each attempt permanently reserves a conservative $0.01, including errors/timeouts, and records completed/failed outcome. This deliberately bounds spend rather than refunding uncertain failed requests. It exceeds worst-case bounded payload/model pricing and needs recalculation if model or bounds change. Counts/outcomes/reserved USD provide usage measurement, not actual provider token/billing telemetry. Service-role access is restricted in code to these two RPCs and never given to inference. Origin validation, Auth token verification, fail-closed live capability checks, 16KB streaming body limit, 1,200-character question bound, 384-token output cap and 15-second provider timeout bound requests.

No unrestricted customer, personnel, messages, finance, inventory or table retrieval exists. Prompt injection cannot produce executable actions, invented links or arbitrary guidance; AI-generated draft summaries remain untrusted text reviewed by the employee. Semantic model selection quality still requires real-model evaluation after activation.
