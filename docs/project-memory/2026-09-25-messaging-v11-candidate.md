## Approved contract and root cause

Preserve private Messaging, universal transfer, picker/paste/drop shared queue, TUS, 50,000,000 bytes/file, 200,000,000 bytes/message, global Storage ceiling 52,428,800, cancellation/retry/recovery and cleanup. Add bounded lazy inline raster previews and recent-first history. Retire **new private Messaging Job links**, with no replacement linking mechanism.

The released `InboxDialog.load()` rebuilt all messages with `attachments: []`, clearing its attachment-cache marker. The attachment effect depended on message IDs, which do not change on read-status updates. A second Realtime load could therefore erase attachment metadata without retriggering its fetch. Full-history requests could also race each other. Hosted `my_work_messages` was already published to Realtime; missing publication was not the cause.

## Implementation

- Atomic authoritative page RPC includes attachment and ready-preview metadata. No separate attachment query or metadata-clearing pass. Stable UUID merge, serialized requests, stale-peer invalidation. Sender's durable transfer identity reconciles into the same map; no provisional duplicate bubble.
- Transactional database broadcast sends only message ID and change kind over the existing participant-authorized private typing topic. Finalization events are delivered after commit. `new` includes draft-to-ready finalization; ordinary updates/deletions reconcile only already-loaded IDs. Sixty-millisecond event coalescing, at most 40 IDs/query, avoids read-mark bursts loading old history. Summary/unread hints coalesce at 100 ms. These are event-driven one-shot timers, not polling.
- Initial latest **40 messages**, stable `(created_at,id)` keyset cursor, older pages on upward scroll or accessible Older messages button. Cursor comes from the page, not late-finalized event rows. Scroll-height delta preserves the prepend anchor. New-message auto-scroll only near bottom/own send. Reconnect refreshes a bounded latest-40 window and resets pagination; older history remains accessible. One initial snapshot plus a post-subscribe snapshot closes the subscription race.
- Conversation summaries carry latest 180-character snippets and authoritative unread counts. Global awareness uses one recipient Postgres Changes channel; no attachment fetch. The active human conversation uses one private channel for both typing and ID hints. Active system conversation uses one recipient-filtered channel. No per-attachment subscriptions. Channel cleanup on close/switch; account-keyed shell unmount handles logout/account switch. Collapsed sidebar has no content channel.
- Optional sender-generated JPEG at `{messageId}/{attachmentId}/preview.jpg` in the **existing private bucket**. Deterministic identity, reserve-before-upload, no upsert. Dedicated RLS metadata table; actual-object trigger locks the parent, checks reserved size and binary MIME, and marks ready transactionally. Tiny direct browser-to-Storage POST; original bytes still use the unchanged private TUS path. Preview request timeout 15 seconds; cancellation aborts it. Preview failure never blocks original finalization/download.
- **1280 px maximum long edge, 196,608 bytes (192 KiB) maximum JPEG.** Source raster header checked before decode; source at most 8192 px per edge / 16 million pixels and within existing 20 MB safe full-preview contract. PNG/JPEG/GIF/WebP supported; GIF is a still frame. Progressive JPEG quality/size reductions bound output. Small valid JPEGs within output bounds are reused without re-encoding. A separate small copy exists so the conversation can never accidentally request an original URL.
- Receiver signs lazily for 120 seconds only within a 200 px viewport margin. Bounded streaming reader rechecks byte count, JPEG signature and dimensions before creating a JPEG Blob URL. No Base64/database payload. Abort/revoke on unmount. Fixed preview geometry, compact two-column multi-image layout, filename/size and independent Download action. Explicit click opens existing original preview. Unknown/active files stay generic/download-only.
- Historical attachments without previews retain generic cards plus explicit Preview image/Download when supported. No eager original fallback, backfill or destructive rewrite.
- Existing cancellation/discard/abandoned cleanup already covers every object under the parent UUID. Admin prepare now includes preview paths; final deletion refuses **any surviving Messaging object under that parent**. Existing deployed Admin Edge accepts these same three-segment paths; no Edge change needed. No new Admin read bypass.
- Attachment-only messages use an empty body only when a durable upload request exists; text-only RPC remains nonempty. Existing size enforcement unchanged.
- `Link a Job`, composer state and the Messaging-only Job-list load are removed. New database insert/changed Job link is rejected, including stale clients/RPC callers. Existing `job_id` values may still be read and preserved on ordinary updates; schema/RPC signatures retained for compatibility. The transfer recovery wire manifest retains its historical `job` field, with new UI sends always null.
