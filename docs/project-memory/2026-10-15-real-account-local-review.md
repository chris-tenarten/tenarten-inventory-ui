URL: http://localhost:3000. Normal TenOps credentials; Chris confirmed his real messages load. Auth is the existing Production Supabase Auth service, reached through the local guard. The proxied endpoint uses Supabase's normal `sb-localhost-auth-token` localStorage namespace, separate from the Production website's origin and synthetic `sb-127` namespace. A matching review session persists on localhost; otherwise sign in normally. No new account/auth infrastructure. Existing Production `.env.local` is read without modification; only its public endpoint/key are used. No service-role key is passed to the app.

The loopback proxy binds before Next starts and supplies the unchanged app with only its guarded local Supabase endpoint. Explicit safe table and RPC allowlists permit authorized reads using the caller's bearer token and Production RLS. Safe RPC POST bodies are converted to GET query arguments; PostgREST GET requests execute read-only transactions (https://postgrest.org/en/stable/references/transactions.html). No caller schema/profile/method override or upstream redirects are forwarded. Unknown RPCs, every Edge Function, Storage operation, Realtime connection/broadcast, business write method and local `/api/` route are denied. Auth is separately limited to password login, token refresh, user lookup and explicitly local logout; signup, recovery, password changes and global logout are blocked. Auth's normal session bookkeeping may occur; business data writes cannot pass the proxy.

CSP is present on the initial response before any application script. It blocks direct hosted fetch/XHR/WebSocket/Beacon, external resource loads, workers and external form submissions. Only local Next HMR WebSocket upgrades pass the proxy. Missing explicit flag, invalid configuration, bind errors, upstream failure and unrecognized operations never fall back to unrestricted access. The indicator is CSS-only to avoid altering React's hydrated body. Next's navigation headers are forwarded. The internal Next port 3017 is an implementation detail; use the protected localhost:3000 URL.

Saving/sending/uploading are blocked at the boundary rather than rewriting application permissions or composer code. Buttons may still look enabled and show errors when clicked; draft text remains editable and locally recoverable. Welcome and read-receipt attempts return explicit 403 errors. Realtime, attachment downloads/previews, PDF generation, account recovery and nonallowlisted reads are unavailable. Some module panels may show unavailable/read-only errors. The launcher and guard are local review tooling, never a hosted security policy. Normal synthetic launcher/tests remain available when switching back; only one candidate owns port 3000.
