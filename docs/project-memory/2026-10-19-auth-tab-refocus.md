## Correction

Retain the already-verified decision only for continuing SIGNED_IN/TOKEN_REFRESHED:
identical token, or matching user/sub and Supabase JWT session_id across rotation.
User ID alone is insufficient. Missing/unreadable continuity claims on a changed
token require blocking validation. Every handled event still requests access.
Generation and current-session checks reject stale responses. Denied/missing/
failed results clear verified access. Sign-out and distinct logins invalidate
immediately. Stabilize refreshProfile callback identity across continuing events
so Samples does not revalidate again due solely to callback identity changes.
No shell, animation flag, token-refresh or backend changes.
