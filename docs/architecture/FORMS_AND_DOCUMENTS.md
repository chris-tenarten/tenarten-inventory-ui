# Forms and Documents

Purchase Orders are the first TenOps Form. Future Letters of Transmittal, Quote Requests, vendor forms, and shop documents must reuse the same separation of concerns:

1. Structured business record or current editor state.
2. A document-specific print model.
3. One canonical document renderer.
4. The shared `DocumentViewer` presentation shell.

`DocumentViewer` owns preview chrome, loading and error states, filename and metadata, zoom, open/download/print actions, attachment sequencing, responsive overlay behavior, and unsupported-file fallback. It does not own Purchase Order layout or calculations.

Draft preview remains a browser renderer for current editor state. Permanent Purchase Order PDFs are first-class business documents with their own deterministic renderer. That renderer accepts only the immutable issuance header and line snapshots through a document-specific model; it never prints the React UI or queries current Vendor, Job, Catalog, or draft records.

Permanent artifacts are generated by a Supabase Edge Function and stored once in the private `purchase-order-documents` bucket. Generation is independent from issuance, retryable after failure, and one-to-one with an issuance. Download returns the stored artifact through a short-lived signed URL and never regenerates it.

Production attachments use signed storage URLs and the same viewer for PDF, PNG, JPEG, and WebP. Unsupported types retain open/download access without unreliable conversion.

Future Forms and Production launch points must open the shared `PurchaseOrderEditor`; there is no separate job-specific PO implementation. Save Draft never generates an artifact. Successful issuance initiates a best-effort permanent-PDF request, while explicit status, retry, and original-download actions remain available on the issued record. Pending Receivals, revisions, and vendor delivery remain separate post-issuance extensions.
